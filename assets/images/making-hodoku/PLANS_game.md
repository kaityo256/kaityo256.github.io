# Hodoku ゲーム実装計画

## 1. 目的

本ファイルは、Godot 4 を用いて Hodoku のゲーム部分を実装するための仕様書である。

問題生成側の仕様は `PLANS_make.md`、プロジェクト全体の共通仕様は `PLANS.md` を参照すること。

ゲーム側では、生成済みの問題データとピクセルアートデータを読み込み、プレイヤーが宝石を交換してボンドをほどき、完成絵を出現させるパズルゲームを実装する。

## 2. 対象環境

- Godot 4 を使用する。現在の開発・検証環境は Godot 4.7.1 とする。
- PC とスマートフォンの両方に対応する。
- 入力は以下の両方に対応する。
  - マウスクリック
  - タッチ
- UI は英語とする。
- 画面サイズやアスペクト比が異なっても、盤面と主要UIが画面内に収まるレスポンシブなレイアウトとする。
- 専用の起動画面は設けず、黒背景からタイトル画面へ直接遷移する。
- 初期実装ではGodot標準フォントを使用し、専用フォントは後から検討する。

## 3. ゲーム全体構成

4段階の難易度を用意し、各難易度は10問とする。

- EASY: 4x4
- NORMAL: 6x6
- HARD: 8x8
- NIGHTMARE: 10x10

各レベルには10個の問題と、それぞれに対応する完成ピクセルアートを用意する。

進行条件は以下とする。

- EASYとNORMALは最初から解放する。
- 各難易度は10問すべてを解くとクリアとする。
- EASYクリア時は専用クリア画面を表示しない。
- NORMALクリア時にNORMALクリア画面を表示し、HARDを解放する。
- HARDクリア時にHARDクリア画面を表示し、NIGHTMAREを解放する。
- NIGHTMAREクリア時にNIGHTMAREクリア画面を表示する。

## 4. タイトル画面

タイトル画面には以下を表示する。

- タイトル `HODOKU`
- `EASY`
- `NORMAL`
- HARDクリア後のみ `NIGHTMARE`
- `HOW TO PLAY`
- `SETTINGS`

`HOW TO PLAY` は常に `SETTINGS` の直上に置く。Web版を含む通常起動ではDEBUGボタンを表示せず、ゲーム引数 `--debug` を明示した場合のみ表示する。

背景は黒を基調とし、低輝度で魔法陣を表示する。

魔法陣はタイトル背景画像 `background_title.png` に含め、独立した透過PNGまたはSVGアセットは用意しない。文字の視認性を妨げない濃度で背景画像へ描き込む。

## 5. 問題選択画面

各レベルにつき10問を選択可能とする。

### 5.1 問題パネル

未クリア問題は数字のパネルとして表示する。

例:

- `1`
- `2`
- ...
- `10`

クリア済み問題は数字の代わりに、その問題の完成ピクセルアートを表示する。

必要であれば小さなチェックマークを重ねてもよいが、完成ピクセルアートが主表示となるようにする。

クリア済み問題は色調とチェック表示で識別し、問題番号の行間を広げ、その下に過去の最小手数 `MIN MOVES` を表示する。

### 5.2 難易度移動

- EASYとNORMALは初期状態から選択できる。
- NORMALクリア後はHARDへ移動できる。
- HARDクリア後はNIGHTMAREへ移動でき、タイトルにもNIGHTMAREを表示する。
- 未解放の難易度は選択画面を表示しない。

### 5.3 難易度クリア演出

NORMAL、HARD、NIGHTMAREの10問を完了した時点で、各難易度の専用クリア画面を初回表示する。NORMALでは `HARD UNLOCKED`、HARDでは `NIGHTMARE UNLOCKED` を通知する。

一度クリアした難易度では `TOTAL MOVES` として全10問のBest Moves合計を表示し、問題選択画面から専用クリア画面をいつでも再表示できる。

## 5.4 HOW TO PLAY

5枚のPNGで、宝石の選択、別宝石との交換、再タップによる選択解除、固定宝石、上下左右の接続による閉路完成を説明する。ナビゲーションの `BACK`、`PREV`、`NEXT` は画像へ描き込まずプログラムで表示する。1ページ目には `PREV`、5ページ目には `NEXT` を表示しない。スマートフォンでは左フリックで次、右フリックで前のページへ移動できる。

## 6. 問題データ

ゲーム用問題データは JSON とする。

問題JSONには少なくとも以下を含める。

- `version`
- `id`
- `width`
- `height`
- `cycle`
- `fixed`
- `initial`
- `pattern`

`pattern` は対応する完成ピクセルアートのIDまたはファイル名を示す。

`initial[position] = jewel_id`

と定義し、問題開始時の配置は毎回同じとする。

ゲーム開始時にランダムシャッフルは行わない。

正解配置は

`solution_position[jewel_id] = jewel_id`

である。

## 7. ピクセルアート

完成絵は以下を用意する。

- 4x4: 10個
- 6x6: 10個
- 8x8: 10個
- 10x10: 10個

合計40個。

モチーフは、低解像度でも認識しやすい単純なシルエットを優先する。

例:

- heart
- key
- star
- moon
- flower
- car
- fish
- cat
- house
- crown

など。

ピクセルアートはJSONで管理し、各セルには固定6色のパレットインデックスを保存する。

### 7.1 固定6色

以下の6色を使用する。

- Red: `#E74C3C`
- Orange: `#F39C12`
- Yellow: `#F1C40F`
- Green: `#2ECC71`
- Blue: `#3498DB`
- Purple: `#9B59B6`

パレットは絵ごとに変更しない。

各ピクセルアートは、この6色のみを使用する。

目安として、

- 4x4: 2〜4色
- 6x6: 2〜4色
- 8x8: 3〜5色
- 10x10: 3〜6色

程度を推奨する。

### 7.2 ピクセルアート生成

初期40パターンはCodex生成のものを仮採用し、その後8x8と10x10を更新している。人間が制作した正式パターンは、同じJSON形式とID参照を維持して差し替え可能とする。

Codexには以下も作成させる。

- パターンJSON
- プレビューPNG生成スクリプト
- バリデーションスクリプト

バリデーションでは少なくとも以下を確認する。

- `width * height == pixels.size()`
- 色インデックスが有効範囲内
- ファイル名とIDが重複しない
- 指定サイズとデータサイズが一致する

最終的な採用可否はプレビューを見て人間が判断し、必要なら修正する。

## 8. 宝石アセット

宝石は固定6色とする。

基本宝石PNG:

- `gem_red.png`
- `gem_orange.png`
- `gem_yellow.png`
- `gem_green.png`
- `gem_blue.png`
- `gem_purple.png`

状態表示用オーバーレイ:

- `overlay_selected.png`
- `overlay_fixed.png`

合計8アセットを基本構成とする。

### 8.1 通常宝石

- 丸すぎない多角形の宝石を基本とする。
- 六角形、八角形、またはカットされた円形などを想定する。
- 上側にハイライトを入れる。
- 下側はやや暗くする。
- 外周に細い縁を付ける。
- 全6色で形状は共通とする。

### 8.2 選択状態

選択状態でも宝石本体の色は変えない。

`overlay_selected.png` を重ね、

- 明るいリング
- 太めの輪郭
- 小さな sparkle
- 軽い発光

などで選択中であることを示す。

必要であれば Godot 側で軽い拡大や脈動アニメーションを追加してよい。

### 8.3 固定状態

固定宝石でも宝石本体の色は変えない。

`overlay_fixed.png` を重ね、

- 金属フレーム
- 四隅の留め具
- 台座
- 必要なら小さなロック意匠

などで動かせないことを示す。

固定宝石は選択不可なので、選択状態と固定状態の同時表示は不要。

## 9. ボンド描画

ボンドはPNGアセットを使用せず、Godotで動的に描画する。

描画順は以下とする。

1. 全ボンド
2. 宝石本体
3. 選択・固定オーバーレイ
4. 必要なUI

ボンドは宝石中心間を直線で結ぶ。

宝石を後から描画するため、線端が宝石中心まで伸びていても宝石によって自然に隠れる。

### 9.1 ボンド状態

両端の宝石の現在位置を格子座標で比較し、

`|dx| + |dy| == 1`

なら隣接していると判定する。

- 隣接しているボンド: 青白い色
- 隣接していないボンド: 赤系の色

完成判定も同じ条件を使用する。

### 9.2 選択宝石のボンド

選択中の宝石から伸びる2本のボンドは、元の青白または赤の意味を維持したまま強調する。

- 通常より線を太くする
- 外側に淡い白色の発光を追加する

色そのものを別の状態色へ変更しない。

### 9.3 ボンド交差

ゲーム途中ではボンド同士が交差してよい。

交差点自体に専用マーカーは表示しない。

### 9.4 交換アニメーション

宝石交換中は、宝石の移動に合わせてボンドもリアルタイムに追従させる。

## 10. 操作

### 10.1 宝石選択

可動宝石をクリックまたはタップすると選択状態になる。

別の可動宝石を選択すると、2個の宝石を交換する。

選択済みの宝石を再度クリックまたはタップすると選択解除する。

固定宝石は選択できない。

### 10.2 宝石交換

任意の2個の可動宝石を交換できる。

隣接している必要はない。

交換は短いアニメーションで行う。

目安として 0.2〜0.3 秒程度とし、最終的な値は実装時に調整してよい。

交換アニメーション中は追加入力を無効化する。

交換完了後に、

- 手数を1増やす
- ボンド状態を更新する
- クリア判定を行う

### 10.3 Undo

`UNDO` を用意する。

1回押すごとに直前の1交換を戻す。

Undo可能な履歴がない場合は無効状態にする。

Undoによる戻し操作では手数を適切に巻き戻す。

### 10.4 Restart

`RESTART` を用意する。

現在の問題を `initial` 配列の状態へ戻す。

手数も0へ戻す。

必要であれば確認ダイアログを表示してよい。

## 11. 手数

問題中に現在の交換回数を

`MOVES`

として表示する。

手数はクリア条件や評価には使用しない。

各問題のクリア時手数をセーブデータへ記録する。

一度クリア済みの問題を再クリアした場合は、Best Moves を採用する設計としてよい。

## 12. クリア判定

すべてのボンドについて、

`|dx| + |dy| == 1`

が成立したらクリアとする。

クリア判定には宝石の色情報を使用しない。

クリアした瞬間からプレイヤー入力を無効化する。

## 13. クリア演出

クリア演出は以下を基本とする。

1. 最後の交換が完了する。
2. 全ボンドが青白になった状態を短時間見せる。
3. 宝石とボンドを軽く発光させる。
4. 宝石を少し縮小させる。
5. 各宝石と同じグリッド位置に、同じ色の正方形ピクセルを出現させる。
6. 宝石とボンドをフェードアウトする。
7. 完成したピクセルアートのみを残す。
8. `CLEAR!` を表示する。
9. プレイ中BGMを停止し、非ループのクリア曲を再生する。
10. `LEVEL SELECT` を表示する。

必要であれば `NEXT PUZZLE` を後から追加してよいが、初期実装では `LEVEL SELECT` を基本とする。

演出時間はテンポを損なわない短めの構成とし、実装時に調整してよい。

## 14. 背景と世界観

基本背景は黒とする。

盤面背後に低輝度の魔法陣を表示する。魔法陣はゲーム背景画像 `background_puzzle.png` に含め、独立した透過PNGとしては用意しない。

世界観は、

- crystal
- magic
- dark background
- soft glow

を基本とする。

宝石、青白いボンド、魔法陣が視覚的に調和するようにする。

## 15. 音響

### 15.1 BGM

BGMは3曲用意する。

3曲の作曲にはSunoのProプランを使用する。

1. タイトル / Level Select BGM
   - 神秘的
   - 魔法的
   - 落ち着いた雰囲気

2. ゲーム中BGM
   - 長時間聴いても集中を妨げない
   - ループ可能
   - タイトル曲より控えめ

3. クリア画面用BGM
   - 通常ステージクリアと難易度クリアで共通使用する
   - 再生前に現在のBGMを停止する
   - ループしない

タイトル画面と問題選択画面では同じBGMを継続してよい。

ゲーム開始時にはゲームBGMへ切り替える。

必要であれば短いクロスフェードを入れる。

クリア画面から問題選択またはメニューへ戻った時点で、タイトル / 問題選択BGMを再開する。従来のクリアジングルは使用しない。

### 15.3 効果音

以下の7種類程度を用意する。

1. 宝石選択
2. 宝石選択解除
3. 宝石交換
4. 固定宝石タップ時の低い「ブブッ」というエラー音
5. UI決定音
6. Level切替音
7. クリア直前 / ピクセルアート出現時の上昇・魔法系効果音

ボンドが青白・赤へ変化するたびの専用音は付けない。

ホバー音も必須としない。

`BACK` は既存のUI音を共用してよい。

音響全体は、8-bit電子音よりも

- glass
- crystal
- soft magic

を基調とする。

固定宝石エラー音のみ、鈍く低い音として対比させる。

## 16. Settings

Settings 画面を用意する。

以下を設定可能とする。

### 16.1 BGM

- 左側に ON/OFF ボタン
- 右側に音量スライダー

### 16.2 SFX

- 左側に ON/OFF ボタン
- 右側に音量スライダー

ON/OFF状態と音量はセーブする。

Godot の Audio Bus を利用し、

- Master
- BGM
- SFX

などを分離して管理する。

## 17. セーブデータ

Godot の `user://` 以下に保存する。

最低限以下を保存する。

- 各問題のクリア状態
- 各問題のクリア手数
- NORMAL / HARD / NIGHTMARE のクリア状態から導出する解放状態
- NORMAL Clear 演出の表示済み状態
- HARD Clear 演出の表示済み状態
- NIGHTMARE Clear 演出の表示済み状態
- BGM ON/OFF
- BGM音量
- SFX ON/OFF
- SFX音量

途中の問題配置は保存しない。

問題から離れて再度入った場合は `initial` 配列から開始する。

## 18. セーブデータリセット

Settings 内に

`RESET PROGRESS`

を用意する。

誤操作防止のため確認ダイアログを表示する。

例:

`Reset all progress?`

ボタン:

- `CANCEL`

リセット対象はゲーム進行状況と手数記録とする。

BGM/SFX設定を同時に初期化するかどうかは実装時に分離可能とし、基本的には進行状況のみをリセットする設計を推奨する。

## 21. 実装上の設計方針

- 問題ロジックと表示を分離する。
- 宝石の接続関係はデータとして保持し、表示ノードの状態から逆算しない。
- ボンド描画は専用ノードまたは専用描画クラスへ分離する。
- 盤面の格子座標と画面座標を明確に分離する。
- クリア判定は格子座標のみを使用する。
- 色はクリア判定に使用しない。
- 入力処理はクリックとタッチを共通化する。
- アニメーション中は入力をロックする。
- セーブ、音響、シーン遷移は可能な限り専用Managerへ分離する。
- 4x4 / 6x6 / 8x8 / 10x10 を同一コードで扱い、サイズ別にロジックを分岐しすぎない。
- PC / スマートフォンで同じゲームロジックを使用する。

## 23. 完了条件

以下を満たした時点でゲーム実装を完成とする。

- 4x4 / 6x6 / 8x8 / 10x10 の問題を読み込める。
- PCとスマートフォンで操作できる。
- マウスクリックとタッチの両方で遊べる。
- 宝石交換、Undo、Restartが正しく動作する。
- 固定宝石を操作できない。
- ボンド状態が正しく青白 / 赤で表示される。
- 選択中の宝石のボンドが強調表示される。
- 正しい配置でのみクリアする。
- クリア時に完成ピクセルアートが表示される。
- 各レベル10問を選択できる。
