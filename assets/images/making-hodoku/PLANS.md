# Hodoku 開発計画

## 1. 概要

Hodoku は、日本語の「ほどく」に由来するパズルゲームである。

偶数×偶数の正方格子上に宝石を配置し、宝石同士を結ぶボンドを「ほどく」ことを目的とする。プレイヤーは可動宝石を選択し、別の可動宝石と位置を交換する。

完成状態では、すべての宝石を通る1本の閉路が形成される。

開発は以下の2フェーズに分ける。

- 問題生成: `PLANS_make.md`
- ゲーム実装: `PLANS_game.md`

本ファイルでは両フェーズに共通する仕様のみを定義する。

## 2. パズルの基本仕様

- 格子サイズは偶数×偶数とする。
- ゲームで使用する格子サイズは `4x4`、`6x6`、`8x8`、`10x10` とする。
- 各格子点には宝石が1個置かれる。
- 各宝石は他の2個の宝石とボンドで接続される。
- ボンドの接続関係は宝石に付随し、宝石を交換しても変化しない。
- 宝石には可動宝石と固定宝石がある。
- 可動宝石同士は、格子上の距離に関係なく任意に交換できる。
- 固定宝石は移動できず、交換相手としても選択できない。

## 3. 完成状態

完成状態では、すべてのボンドが上下左右に隣接する格子点間を結ぶ。

したがって完成状態のボンド全体は、格子グラフ上の全格子点をちょうど1回ずつ通るハミルトンサイクルとなる。

ゲームのクリア判定は、すべてのボンドが上下左右に隣接する格子点を結んでいることによって行う。

## 4. 解の一意性

問題生成時には、以下を満たすことを要求する。

> 固定宝石を指定した状態で、すべてのボンドが上下左右の隣接格子点を結ぶような宝石配置が、正解配置ただ1つだけ存在する。

宝石の色情報は一意性判定には使用しない。

固定宝石は一意解を保証するために使用する。固定宝石の個数は少ない方が望ましいが、最小固定集合である必要はない。

## 5. 宝石の色と完成絵

ハミルトンサイクルとは独立して、格子サイズごとに複数のピクセル絵を用意する。

例:

- `4x4`
- `6x6`
- `8x8`
- `10x10`

正解配置の各格子点に対応する色を各宝石へ割り当てる。

そのため、プレイ中には色がシャッフルされて見えるが、パズルを解くと宝石の色によって完成絵が浮かび上がる。

色情報はパズルの解法および一意性には影響しない。

## 6. データ形式

問題データには JSON を使用する。

C++ 問題生成器の基本出力は以下の情報を持つ。

- `version`
- `width`
- `height`
- `seed`
- `index`
- `cycle`
- `fixed`

格子点IDは row-major order で

`id = y * width + x`

と定義する。

`cycle` は宝石IDをハミルトンサイクル順に並べた配列とする。

`fixed` は正解位置に固定する宝石IDの配列とする。

正解配置では、宝石IDと格子点IDを一致させる。

`solution_position[jewel_id] = jewel_id`

とする。

絵データはサイクルデータとは独立して管理し、最終的なゲーム用問題データを作成する段階で組み合わせる。

## 7. 問題生成器の共通インターフェース

問題生成器は C++ で実装し、入力は YAML とする。

YAML では少なくとも以下を指定する。

- `size`: 実際の格子幅。偶数のみ許可する。
- `seed`: 生成プロセスの基準乱数シード。
- `count`: 生成する問題数。

例:

```yaml
size: 6
seed: 12345678
count: 100
```

問題生成器は複数プロセスから同時実行されることを前提とする。

出力 JSON のファイル名には少なくとも以下を含め、別プロセスとの衝突を避ける。

- 格子サイズ
- 基準乱数シード
- 問題番号

推奨形式:

`puzzle_<size>x<size>_s<seed>_n<index>.json`

例:

`puzzle_6x6_s12345678_n000017.json`

JSON 内にも `seed` と `index` を保存し、ファイル単体から生成条件を追跡できるようにする。

現在の問題生成器では外部依存を避けるため、上記3項目のスカラー形式に限定した YAML 読取器を使用する。未知キー、重複キー、必須キーの欠落、不正な整数値はエラーとして拒否する。将来、入れ子や配列など設定形式を拡張する場合は、single-header / header-only の `fkYAML` を第一候補として導入する。

## 8. ディレクトリ構成

問題生成器と Godot 4 ゲーム本体をトップレベルで分離する。

```text
.
├── PLANS.md
├── PLANS_make.md
├── PLANS_game.md
├── maker/
│   ├── CMakeLists.txt
│   ├── src/
│   ├── include/
│   ├── third_party/
│   ├── config/
│   ├── output/
│   └── tests/
└── game/
    ├── project.godot
    ├── scenes/
    ├── scripts/
    ├── assets/
    └── data/
        ├── patterns/
        └── puzzles/
```

`maker/output/` は問題生成器の生出力を保存する場所とする。

Godot で実際に採用する問題は、変換スクリプトを介して `game/data/puzzles/` に配置する。問題生成器の生出力とゲーム採用データを同一ディレクトリで直接共有しない。

## 9. 実装フェーズ

### 問題生成

`PLANS_make.md` に詳細を記述する。

原則として `maker/` 以下のみを変更する。

主な処理は以下とする。

- YAML 設定の読み込み
- ランダムなハミルトンサイクルの生成
- 固定宝石の決定
- 解の一意性判定
- 冗長な固定宝石の削減
- JSON 出力

多数の問題を生成するためのプロセス並列化は、このプログラムの外側で行う。問題生成器自体はシリアル実装とする。

### ゲーム

`PLANS_game.md` に詳細を記述する。

原則として `game/` 以下のみを変更する。

Godot 4 を使用し、主に以下を実装する。

- 問題 JSON の読み込み
- 宝石とボンドの表示
- 可動宝石の選択と交換
- 固定宝石の扱い
- クリア判定
- 色および完成絵の表示
- 問題ごとに保存された固定初期配置の読み込み

## 10. 設計上の原則

- 問題の論理構造と色情報を分離する。
- 問題生成とゲーム実装を分離する。
- JSON を両者のインターフェースとする。
- 正解判定および一意性判定に色情報を使用しない。
- データから導出可能な情報は可能な限り重複して保存しない。
- 問題生成アルゴリズムの詳細は `PLANS_make.md` に集約する。
- Godot 側の実装詳細は `PLANS_game.md` に集約する。

## 11. 現在の実装状況

2026年8月13日時点で、`maker/` の初期実装と `game/` のゲーム初期実装は完了している。

- C++17 / CMake / Ninja によるビルド
- YAML 設定の読み込みと検証
- 問題単位で独立した再現可能な乱数 seed の導出
- randomized DFS の粗格子全域木によるハミルトンサイクル生成
- サイクルの頂点数、重複、隣接辺の検証
- DFS / backtracking による別解探索
- 固定位置、Manhattan 距離、parity、残り領域の連結性、低次数の枝刈り
- 別解との差分を用いた固定宝石追加と冗長固定宝石削減
- `problem_seed` を含む JSON 出力
- CTest による単体テスト
- 回転・反転を考慮した等価問題検査

現行対象の4x4、6x6、8x8、10x10は各10問以上を実生成済みであり、ゲームではサイズごとに10問を採用する。6x6、8x8、10x10では各10種類の異なるハミルトンサイクルを使用し、4x4では盤面サイズ上の制約から4種類のサイクル形状を10問に割り当てる。4x4では、同じ入力から同一 JSON を再生成できることも確認済みである。`maker/output/` の生成JSONとビルド生成物は Git の管理対象外とする。

ゲーム側では以下を実装済みである。

- Godot 4.7.1 プロジェクトと、起動画面を表示せずタイトルへ直接進む構成
- タイトル、問題選択、パズル、HOW TO PLAY、Settings、クリア・進行演出
- 4x4、6x6、8x8、10x10の各10ステージ
- 宝石交換、Undo、Restart、Moves、固定宝石、ボンド描画とクリア判定
- 各難易度10問完了によるクリア、NORMAL→HARD→NIGHTMAREの段階解放
- 進行状況、Best Moves、難易度別Total Moves、音量設定の `user://save.json` への保存
- Suno Proプランを使用して作曲したループBGM 2曲と非ループのクリア曲1曲、および効果音7種類の統合
- 固定6色の宝石、選択・固定オーバーレイ、タイトル・パズル背景
- 仮のピクセルアート40個とブラウザ用ピクセルアートエディタ
- 全40ステージのデータ検証とGodot上の盤面ロジック自動テスト
- Web版を含む通常ビルドではDEBUG UIを非表示とし、`--debug` 指定時のみ表示
